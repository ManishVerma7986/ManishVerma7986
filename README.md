## 👋 Who Am I?

I'm **Manish Verma**, a Computer Science graduate with a strong interest in software development, intelligent applications, backend engineering, and machine learning.

My development journey revolves around one central idea: **technology becomes valuable when it solves a real problem.**

Rather than limiting myself to one technology, I enjoy exploring the complete software development process — understanding a problem, planning the architecture, developing application features, connecting APIs and databases, testing functionality, and improving the final user experience.

My projects reflect this multidisciplinary approach. I've explored document-grounded AI assistants, machine-learning applications, career guidance, emergency routing, multiplayer gaming, banking software, and AI-assisted software project estimation.

### 🎯 What Defines My Development Approach

* **Problem-first engineering:** Understand the underlying problem before choosing a solution.
* **Practical AI:** Build applications where AI and machine learning serve a clear purpose.
* **Full-stack thinking:** Consider the frontend, backend, data layer, integrations, and deployment together.
* **Reliability matters:** Value validation, meaningful error handling, testing, security, and maintainable code.
* **Continuous improvement:** Learn by building, debugging, evaluating, and refining real projects.

I'm particularly interested in opportunities where I can contribute to software products, learn from experienced engineers, and grow into a well-rounded software engineer.

## 🥇 01. Costimator — AI-Powered Software Cost Estimation Platform

<p>
  <a href="https://github.com/ManishVerma7986/cost-esitimatio-KLE-HACKFEST">
    <img src="https://img.shields.io/badge/VIEW%20PROJECT-00D9FF?style=for-the-badge&logo=github&logoColor=black" alt="View Costimator"/>
  </a>
  <img src="https://img.shields.io/badge/Domain-Software%20Engineering-7C3AED?style=flat-square" alt="Software engineering"/>
  <img src="https://img.shields.io/badge/Focus-Estimation%20%26%20Risk-059669?style=flat-square" alt="Estimation and risk"/>
</p>

**The problem:** Software teams need more than a rough guess to estimate development effort, schedules, infrastructure costs, and project budgets.

**The solution:** Costimator is designed to turn project requirements into structured work breakdowns and data-informed estimates, while making uncertainty and financial assumptions visible.

**Technical highlights documented in the repository:**

* 🧩 AI-assisted decomposition of requirements into a Work Breakdown Structure (WBS).
* 📐 Hybrid estimation using COCOMO II, LightGBM, and historical-project similarity.
* 🎲 Monte Carlo simulations for uncertainty and risk analysis.
* 💰 Total Cost of Ownership (TCO) estimates covering labor, cloud infrastructure, tools, and contingency.
* 🔀 What-if scenarios for different budgets, schedules, and project constraints.
* 📑 Export-oriented reporting and structured estimation APIs.
* 🔐 Documented attention to input sanitization, audit trails, and model provenance.

**Technologies:** Python · FastAPI · Streamlit · LightGBM · NumPy · SQLAlchemy · SQLite/PostgreSQL

**Why it stands out:** It combines software engineering, machine learning, financial modeling, and uncertainty analysis into one engineering-focused product.

🔗 [Explore Costimator](https://github.com/ManishVerma7986/cost-esitimatio-KLE-HACKFEST)

## 🥈 02. SafeRoute — Disaster-Aware Emergency Routing System

<p>
  <a href="https://github.com/ManishVerma7986/Disaster-management-and-routing-system">
    <img src="https://img.shields.io/badge/VIEW%20PROJECT-00D9FF?style=for-the-badge&logo=github&logoColor=black" alt="View SafeRoute"/>

**The problem:** During emergencies, the shortest route may not be the most appropriate route if roads are closed or hazards affect accessibility.

**The solution:** SafeRoute is a disaster-aware routing system designed to prioritize safety-oriented route selection, communicate hazard information, and support emergency-related workflows.

**Technical highlights documented in the repository:**

* 🗺️ Flutter mobile application with GPS and OpenStreetMap-based route maps.
* 🛣️ Risk-aware routing and alternative-route foundations.
* 🚧 Authority-managed road closures and incident reporting.
* 🔑 Authentication and role-based access using JWT.
* 📍 Cached route support and offline-status awareness.
* 🏥 Emergency-related facilities and hazard-reporting workflows.
* ⚙️ FastAPI backend with persistent data and database migration support.
* 🧪 Documented local validation of Flutter analysis, tests, and release builds.

**Technologies:** Flutter · Dart · Python · FastAPI · PostgreSQL · PostGIS · SQLite · OpenStreetMap · JWT · Alembic

**Why it stands out:** It combines mobile engineering, geospatial data, backend APIs, and safety-conscious application design around a real-world problem.

**Engineering note:** External provider configuration, physical-device validation, background location, and some predictive or live-data integrations have documented limitations or remaining work.

## 🥉 03. Domain-Specific RAG Chatbot — Document-Grounded AI

<p>
  <a href="https://github.com/ManishVerma7986/ragChatBot">
    <img src="https://img.shields.io/badge/VIEW%20PROJECT-00D9FF?style=for-the-badge&logo=github&logoColor=black" alt="View RAG chatbot"/>
  </a>
  <img src="https://img.shields.io/badge/Domain-Generative%20AI-7C3AED?style=flat-square" alt="Generative AI"/>
  <img src="https://img.shields.io/badge/Focus-RAG%20%26%20Retrieval-DB2777?style=flat-square" alt="RAG"/>
</p>

**The problem:** Finding precise answers in long PDF documents is time-consuming, while a general-purpose language model may generate answers that aren't supported by the documents.

**The solution:** A document-grounded assistant that lets users upload PDFs and ask natural-language questions, with answers tied to retrieved document content.

**Technical highlights documented in the repository:**

* 📄 Multiple PDF uploads and page-by-page text extraction.
* ✂️ Text chunking with document and page metadata.
* 🧠 Sentence Transformer embeddings.
* 🔎 FAISS similarity search for relevant passages.
* 💬 LLM integration with configurable providers.
* 📚 Source-document and page references alongside answers.
* 🛡️ Guardrails against unsupported answers and prompt-injection attempts.
* 🧪 Documented test workflow and graceful handling of common file and API errors.

**Technologies:** Python · Streamlit · LangChain · Sentence Transformers · FAISS · pypdf · LLM APIs

**Why it stands out:** It demonstrates the end-to-end RAG workflow — from ingestion and embeddings to retrieval, grounded generation, and source attribution.

🔗 [Explore the RAG Chatbot](https://github.com/ManishVerma7986/ragChatBot)

# 🧪 How I Approach Engineering

I aim to think beyond making a feature work once. I care about the way a complete application behaves.

* **Requirements:** Break a problem into understandable features and constraints.
* **Architecture:** Separate responsibilities across the interface, backend, data layer, and integrations.
* **Data integrity:** Validate input and handle missing or invalid information explicitly.
* **Security:** Protect secrets, enforce access controls, and treat external input carefully.
* **Testing:** Verify important workflows and edge cases through repeatable checks.
* **Observability:** Make failures easier to understand through useful errors and logs.
* **Deployment:** Consider configuration, environment variables, service dependencies, and operational limitations.
* **Iteration:** Use testing and debugging to identify gaps and improve the implementation.

These are the engineering principles I aim to apply and strengthen as I continue building more reliable software.
